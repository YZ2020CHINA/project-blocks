## 项目积木可视化协作

用户希望在后续新建本地 Codex 软件项目时自动建立积木画布。开始实际创建或构建一个新项目时，使用已安装的 `project-blocks` skill；若 skill 尚未注入，可读取 `__PROJECT_BLOCKS_SKILL_PATH__`。在实际项目根目录内建立并保留 `project-blocks/data/project.json` 和独立运行工具，调用 skill 的 helper 初始化、启动服务，再用 `open_in_codex` 在当前聊天右侧打开返回的 URL。无需再次询问用户是否需要画布。

只在实际项目目录明确后执行；若当前目录是多个项目的父目录，先建立业务项目子目录再初始化画布。普通问答、只读审查、单次文档操作不自动生成。已有画布复用并按实际工作更新卡片、依赖、状态与验收证据；保持用户卡片和布局，不把示例/未验证工作标记为完成。用户说不需要时跳过。遵守当前权限；不要通过全局规则扩大对其他文件或外部服务的授权。

自动触发发生在新项目首次实际构建对话，不是仅点击侧栏“新建项目”时的后台事件。若 helper 或打开面板工具不可用，应说明具体限制，不声称画布已经打开。

执行期间按 skill 使用进度 helper：开始当前卡片时上报 `doing`，长命令通过 `--run` 自动发送心跳；切换或交还用户前上报待验收、受阻或有证据的完成状态，使右侧画布显示真实执行高亮。旧项目需要动效时先用 `ensure --upgrade --start` 备份升级运行文件，并打开返回的新 URL。
